# Wikilink semantics

Internal Rust component of the Notes kit. The parser reads wikilinks and converts supported links to the canonical HsLink model. The resolver provides an in-memory document index and resolves exact reference/ID first, normalized title second, then alias. Duplicate normalized titles or aliases return explicit ambiguity.

Use the parser and resolver modules exported by src/lib.rs. Populate ResolverIndex through add_document and add_alias, then call resolve_wikilink. normalize_target trims, collapses whitespace and lowercases comparison text; original display text is preserved. Alias state is local to the index and does not establish persisted backend alias support. Missing and ambiguous results must remain visible to the caller.

The host retains GUI interaction, authenticated operations, storage and native CreateNote intent handling. This component does not create notes or invent document identities.

The package depends on `handshake_rich_document_model` at `https://github.com/Nuntissura/assets.git`, pinned to `e75e34ff69ef799c805b8c3f65fbc103953318aa`, and returns its `node::HsLinkNode`. Consumers must use that exact model source/revision for compatible Rust type identity. An explicit published Git pin avoids resolving a same-repository path dependency from a later sibling publication revision. The model owns the link type; this package owns parsing and resolution. No host dependency is required.

Legacy materialization leaves `provenance`, `target_kind`, `target_block_id`, and `tag_ref_kind` absent. It preserves the parsed reference, full display label and known/unknown resolution flag without guessing persisted note/block/tag identities. The canonical ASCII-prefix and whole-token parser behavior is unchanged. A native local copy with Unicode prefix matching or substring parsing is a different source; adopting this crate does not silently reconcile that difference.

`parser::legacy_native` is the explicit compatibility entrypoint for that historical native API. Its `parse_wikilink` returns the first token in trimmed input even when prose or later tokens surround it. Its regex keeps the first prefix character ASCII and uses the historical Unicode-aware word class for later characters; `extract_wikilinks` retains unresolved Unicode-prefix tokens alongside ordinary tokens. Classification, prefix table, parsed types, model conversion and open-query detection reuse the canonical implementation. A host can alias this module to preserve its existing parser API while keeping its stricter production atom gate. Canonical `parser::parse_wikilink`, `wikilink_regex`, and `extract_wikilinks` retain strict whole-token/ASCII defaults. `tests/legacy_native_compatibility.rs` records both sets of behavior, including Code/Locus targets and aliases; no local host parser replacement is performed here.

Cargo resolved the exact model Git source above while preserving all 20 registry entries and the existing dependency edges. The locked compatibility tests passed all 6 cases, and the full crate run passed all 34 tests. `tests/model_compatibility.rs` covers legacy materialization, optional-field absence, canonical model types and JSON round trips; existing parser/resolver tests remain required.

Run `cargo test --locked` from this package directory to verify parser and resolver behavior, including unknown prefixes, normalized title and alias ambiguity, and exact-reference precedence. Host GUI, backend persistence and pinned adoption require separate integration proof.
