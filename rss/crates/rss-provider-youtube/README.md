<topic id="research">

Connected-mode research checked 2026-10-25: Google's [subscriptions.list](https://developers.google.com/youtube/data/reference/rest/v3/subscriptions/list) imports subscribed channels with OAuth `mine`; it does not return their content. The current [activities.list reference](https://developers.google.com/youtube/data/reference/rest/v3/activities/list) deprecates `home`. [Uploaded-video guidance](https://developers.google.com/youtube/data/guides/implementation/videos) resolves the authenticated channel's uploads playlist. [YouTube.js Innertube](https://github.com/LuanRT/YouTube.js/blob/main/src/Innertube.ts) distinguishes `FEwhat_to_watch`, `FEsubscriptions` and `FEchannels`; its HomeFeed/Feed implementations follow body continuation endpoints. Its HTTPClient and yt-dlp's current `_base.py`, `_redirect.py` and `_tab.py` demonstrate session-bound cookies/account selection, cookie rotation, selected-page checks and continuation loops. yt-dlp specifically rejects its former OAuth login path; this does not invalidate Google Data API OAuth.

Reuse the existing bounded JSON admission, video/channel identity, entry evidence and canonical-owner ports. Implement raw selected browse parsing in Rust, with explicit OAuth versus browser-session transport and host-issued nonsecret lease provenance. Reject reconstructing recommendations from imports/uploads, deprecated Home API calls, anonymous fallback and Python/JavaScript runtime delegation. Undocumented renderer changes produce Partial or a typed failure; lease checks surround asynchronous effects and digest-bound replay rejects missing retained bytes. Owning synthetic mode, parsing, pagination and authorization tests precede consumer proof; neither establishes live acquisition or host credential availability.

Research inspected on 2026-10-23 before implementation: Google's [channels.list](https://developers.google.com/youtube/data/reference/rest/v3/channels/list), [playlistItems.list](https://developers.google.com/youtube/data/reference/rest/v3/playlistItems/list), [playlist item resource](https://developers.google.com/youtube/data/reference/rest/v3/playlistItems), [videos.list](https://developers.google.com/youtube/data/reference/rest/v3/videos/list) and [API setup](https://developers.google.com/youtube/data/getting-started). Channels resolve IDs/handles and identify their uploads playlist. Playlist requests accept up to 50 results and return opaque page tokens. Playlist insertion time is distinct from `contentDetails.videoPublishedAt`. Video IDs identify videos globally. Public API requests need host-managed project credentials but do not require a user's connected YouTube account.

Adjacent source inspected: [yt-dlp tab extraction](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/youtube/_tab.py#L527-L583) handles renderer families, continuation loops and changing visitor data. The existing Portal channel reader resolves public channel/handle URLs to a recent Atom document. Select the documented uploads API for paginated public history and expose no-login Atom as an explicit recent-snapshot strategy. Reject treating recent XML as complete channel history, hardcoding Innertube visitor/client state, calling a Python downloader, silently switching to connected accounts, and using playlist item IDs as canonical video identity.

Reuse RSS and hsscrap owner contracts, maintained feed-rs Atom parsing and the published strict JSON admission helper. Host-owned bounded transport and retained snapshots isolate keys, authorization, redirects, DNS rules and caches. Digest-bound offsets, scoped continuations, cycle rejection and stable global video identities address retries, retargeting and repeated pages. Finite limits fail without advancing canonical checkpoints. Native callbacks prove adapter behavior; real selected-channel access, quota availability, complete canonical reconciliation and host persistence require separate gates.

<topic id="connected">

`connected::ConnectedYouTubeProvider<F,C>` implements actual `Following` and `HomeForYou` through browser-session browse requests (`FEsubscriptions` and `FEwhat_to_watch`). OAuth `OwnUploads` resolves `channels.mine` and its uploads playlist; `PrivateSource` accepts one explicit video or playlist. `import_subscriptions` returns bounded `ChannelEvidence` in `SubscriptionPage` through OAuth `subscriptions.mine`; `ProviderPort::acquire` deliberately rejects that mode because imported channels are not acquired content. Unsupported credential/mode combinations never switch strategies. Current browse parsing supports selected rich-grid, section, grid and video renderer containers; unrecognized content is reported Partial, and an empty unrecognized response fails. Current traversal coverage stays Partial. Only explicit zero-count selected API documents can be VerifiedEmpty.

Inject `ConnectedFetchPort::current/fetch` and the existing canonical entry owner. `AuthorizedContext` contains connection/account identity, canonical UC external identity, credential kind, lease generation and exact `CaptureIntent`; no secret. The host must attest the current authenticated account, scope, provider, capture intent and exact lease attempt at every `current` call, reject anonymous fallback, retain exact authorized responses, and hold the credential lease through owner/checkpoint settlement. Data API OAuth and browser-session cookie/auth headers, account index, visitor/client configuration, refresh and expiry remain host-owned. Browse requests return raw JSON and the exact response endpoint `https://www.youtube.com/youtubei/v1/browse`; redirect/auth errors fail. The crate parses selected content itself. Session information must not be reconstructed from a caller's cursor. Authorization is repeated around fetch and canonical preparation and before return; host owner mutation/checkpoint admission must still atomically fence revocation. The shared adapter cannot undo a canonical operation already committed before an authorization change.

Resume cursors bind selection, source revision, mode, connection, external identity, credential kind and the standard subscription/executor/generation envelope. Same-document offsets require retained digest equality; refreshed leases may replay exact retained evidence without changing its observation provenance. No missing snapshot may silently refetch replacement bytes. Metadata cannot grant private visibility; captures retain the supplied authorized access partition. Native contract tests are included in the existing `public` integration target, so run the owning package tests once under the coordinator. These are synthetic adapter proofs; host credential wiring, ordinary-customer authorization and actual connected-source acquisition remain separate unproven boundaries.

</topic>

<topic id="use">

`YouTubeProvider<F,C>` implements public-channel acquisition. Choose `Strategy::PublicApi` for uploads pagination and individual public video metadata, or `Strategy::NoLoginAtom` for the current channel feed. The choice is explicit. Atom feed IDs may contain the full requested UC channel ID or its exact tail; the tail form additionally requires an alternate link resolving to the full requested canonical channel. Video permalinks reuse the native URL resolver and must resolve to the exact entry video ID, including Shorts. Canonical evidence and identity remain youtube/video with watch URLs. Public API transport supplies backend project credentials outside this crate and never includes them in request DTOs, cursors or source URLs. Atom transport attaches no connected-user credentials. Use the separate `connected::ConnectedYouTubeProvider` described above for browser-session Home/Following and OAuth private sources, own uploads and subscription imports. Live host adoption and actual connected-source acquisition remain unproven.

Inject `FetchPort` and `CanonicalEntryPort`. Authorize the source, account/profile scope, executor and attempt before transport and canonical effects. Reuse `rss-acquisition::prepare_entry` and the canonical identity owner with the global identity `youtube/video/<video-id>`. The host allocates canonical IDs and persists ordered media references. Embed URLs are provider player references, thumbnails are previews, and neither proves downloaded video bytes. Merge their Partial gallery evidence without deleting existing members.

`public::resolve_channel_html(bytes, bounds, max_body_bytes)` reuses the acquisition parser to resolve one unique canonical channel from retained handle HTML. The body limit must be nonzero and at most 16 MB. It rejects missing or conflicting canonical channel links, invalid UTF-8 and oversized bodies. It performs no network request. The host must retain and verify the exact authorized handle request, response URL and bytes before using this resolver to bind a channel during acquisition or recovery; HTML alone is not source authority.

Retain raw responses under exact request/operation intent before canonical preparation. An expected digest requires the retained document and must fail if missing or changed. HTTP 304 requires exact authorized cached bytes. Keep continuations in canonical host storage; do not trust caller-edited traversal state. Cursor scope, source revision, channel/playlist identity, provider token, digest/offset and bounded seen IDs are checked before owner effects. One acknowledged page advances through the existing atomic checkpoint boundary. Mutable public traversal and recent XML remain Partial even when no more pages are advertised. Empty feeds alone do not establish an empty channel; errors retain prior data. Only an explicitly verified zero-count uploads response can establish empty API coverage.

After coordinated manifest registration, run `cargo test --locked --manifest-path rss/Cargo.toml -p rss-provider-youtube --tests` under the active preparation gate. Fixture tests use synthetic responses and disposable canonical callbacks. No credentials, live network, database or browser are used by those tests. On missing keys, quota/rate limits, expiry, restricted/deleted entries or changed snapshots, retain the existing checkpoint and report the typed failure or Partial result. Host adoption and actual source acquisition remain unproven until their own gates pass.
