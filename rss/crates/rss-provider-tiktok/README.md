<topic id="research">

Connected research checked 2026-10-25: [opentok endpoints at 2e054400](https://github.com/caixax/opentok/blob/2e0544003945c59016ed7b74c4575bd063774d13/src/main/tiktok/endpoints.ts) separates Following content with its explicit cursor, For You fresh batches without a provider cursor, and selected-profile posts. Its [profile parser](https://github.com/caixax/opentok/blob/2e0544003945c59016ed7b74c4575bd063774d13/src/main/tiktok/parse/user.ts) identifies followed/mutual relationships through relation 1/3. [go-tiktok at b5bfda01](https://github.com/go-tiktok/tiktok/blob/b5bfda01c65ada5c62952e29612e78f60e158556/tiktok.go) supplies an alternate maxCursor dialect and permissive empty defaults; neither is merged into the selected opentok protocol. The [official OAuth video list](https://developers.tiktok.com/docs/en/tiktok-api-v2-video-list) returns only public posts and supplies no private-source permission.

Reuse strict rehydration/JSON admission, native entry/media normalization and canonical owners. A separate browser-session adapter owns connected endpoint selection, identity checks and bounded pagination. Host leases own cookies, signing, device/session state and exact authenticated identity. Private metadata or a relationship alone never grants access: private profile acquisition also requires current viewer authority and a successful exact-target content response. Initial empty private or feed responses remain unverified. Own-profile explicit zero statistics plus successful terminal content may establish VerifiedEmpty. For You resumes only the original immutable retained batch, never a fresh recommendation request. Reject subscription-account imports as Following content, OAuth public posts as private content, anonymous fallback, normalized host feeds and runtime downloader delegation. Contract fixtures cover routing, zero/error separation, retained replay, lease races and public regressions before independent consumer proof; live provider compatibility remains separate.

Current primary sources inspected before implementation on 2026-10-23: [yt-dlp TikTok at 9b58cb3](https://github.com/yt-dlp/yt-dlp/blob/9b58cb33d0cd3e823c8d8732f6adce8faa1f37e3/yt_dlp/extractor/tiktok.py#L998-L1130), [gallery-dl TikTok](https://github.com/mikf/gallery-dl/blob/882c8d0bb5c5a3ed4e88726d2f42a1cb7db59bf2/gallery_dl/extractor/tiktok.py#L67-L92) and [official creator embed documentation](https://developers.tiktok.com/docs/en/embed-creator-profiles). The official embed selects at most ten recent videos. It cannot establish full pagination. yt-dlp reads verified user identity from the public rehydration document, then traverses `creator/item_list` with `secUid`, timestamp windows and `hasMorePrevious`. Gallery-dl supports that route and a separate ordered `post/item_list` route, which it describes as cookie-dependent and flaky. Its image-post parser preserves `imagePost.images` order and image URLs/dimensions.

Select the explicit public creator-window protocol and individual public item rehydration. Reject embed-only history, silently changing endpoint or connected mode, fabricated device IDs, copying a Python worker or executing a downloader. Rust owns URL resolution, raw JSON/HTML normalization, pagination and canonical evidence. Genuine public browser/device context, network signatures, rate policy, address/redirect policy and credentials remain host effects. Reuse RSS/hsscrap contracts, the published strict JSON admission helper and maintained HTML parsing.

Provider endpoints and anonymous access can change or be challenged. A malformed/empty successful HTTP response is not an empty creator. Validate account identity, every page entry and continuation before owner preparation; retain digest-bound page snapshots and finite traversal history. Dates come from explicit `createTime`, never from a bit-shifted item ID. Canonical identity is global `tiktok/item/<post-id>`; member positions are ordering evidence, never invented stable media IDs. Meaningful public-API fixtures cover these invariants; actual public access and canonical host reconciliation remain independent gates.

<topic id="connected">

ConnectedTikTokProvider implements browser-session Following, HomeForYou, OwnUploads and PrivateSource through AuthorizedFetchPort and the existing canonical entry owner. AuthorizedContext binds the selected connection/account, numeric viewer ID, viewer secUID, lease generation and exact FollowSource capture intent. The host freshly attests that authority at every current call, supplies bounded raw responses and retains its lease through canonical settlement. Cookies, request signing, browser/device parameters and refresh remain outside this crate. Mandatory endpoint and selection parameters cannot be overridden by runtime additions.

Following accepts only the declared cursor/pullType/level/from_page protocol. It does not import followed account lists. HomeForYou is one current recommendation batch, not a paginated archive: an offset continuation carries an expected digest selecting the original retained raw body, and never authorizes a fresh batch fetch. The host must return the original observation provenance on retained replay. Renewed attempts may reuse those original bytes under a fresh current lease; login, source, mode, connection or epoch changes cannot reuse the cursor. Following sources use the /following route, Home uses / or /foryou, and selected own/private sources use a profile URL.

OwnUploads requires exact numeric ID and secUID equality with the attested viewer. PrivateSource requires explicit private profile metadata plus the same owner or a followed/mutual relationship, and a successful exact-target content response under the same current authority. Metadata alone supplies no grant. Selected single-item private/own URLs and subscription imports remain Unsupported rather than substituting another stream. Mixed feed entries keep their actual author identity; profile entries must match the selected profile. Initial empty private or feed responses fail as unverified. Only an attested own profile with explicit zero statistics and a successful terminal empty content response can be VerifiedEmpty. Nonempty coverage and continued terminal documents remain Partial.

The adapter cannot undo an owner operation already committed before revocation; canonical mutation/checkpoint settlement must atomically fence the same host lease. Media normalization remains shared with public acquisition, including explicit timestamps, ordered photo evidence, expiring locators and Partial galleries. Contract fixtures cover these boundaries, not actual provider access, private-content compatibility, customer authorization or host persistence.

</topic>

<topic id="use">

`TikTokProvider<F,C>` acquires a selected public creator or individual `/@creator/video/<id>` or `/photo/<id>` URL. Inject bounded `PublicFetchPort`, actual host time through `initial_cursor_millis`, and `CanonicalEntryPort`. The host supplies genuine public browser/request context when the provider requires it; it must not attach a connected user's session or replace Rust normalization with another implementation. Keys and browser state are never embedded in source URLs, provider cursors or fixtures.

The host authorizes scope, source, generation, executor and attempt before each fetch and canonical effect. It retains exact raw responses under immutable page-operation intent. An expected digest selects the retained snapshot and fails if missing or different. Canonical callbacks use existing `rss-acquisition::prepare_entry`, resolve the global provider identity and allocate all item, observation and ordered media IDs. Apply Partial gallery evidence through the owning gallery boundary while preserving existing members. Media URLs are expiring public locators; byte retrieval and expiry recovery belong to the host.

Public creator traversal follows the inspected timestamp-window protocol. Empty continuing windows are consumed within the current bounded acquisition call, because the current checkpoint owner cannot acknowledge empty continuing Partial pages. Do not fabricate such an acknowledgement. Set modest finite fetch/document budgets, ordinarily a small number of requests, and enforce the actual attempt deadline. Exhaustion fails without checkpoint advancement. A larger configured ceiling is only a ceiling, not proof that sparse history makes progress. Actual sparse-history runtime acceptance must verify that the host's budget reaches an item or terminal window. The adapter never issues a giant default burst and has no automatic retry or route fallback.

Nonempty traversal remains Partial even at advertised exhaustion, because public timestamp windows cannot prove an immutable complete archive. A terminal empty page reached from a canonical continuation settles only that traversal. An initial empty result requires verified public profile statistics explicitly reporting zero posts and an actual terminal response; otherwise it fails. The separate connected adapter described above preserves its own modes and authority; live connected-source compatibility remains unproven.

After coordinated registration, the build owner runs `cargo test --locked --manifest-path rss/Cargo.toml -p rss-provider-tiktok --tests` under the active preparation gate. Public and connected fixtures share the public integration target and run once. Synthetic raw responses and disposable callbacks prove only the adapter contract. No live source, browser session, persistent database, canonical owner integration or host adoption is claimed by those fixtures.

</topic>
