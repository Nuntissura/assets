<topic id="use">

`PinterestProvider<F,C>` supports public board URLs, board-section URLs, explicit `/user/pins/` sources and single `/pin/<id>/` item URLs. A root `/user/` URL is board discovery, not silently an all-pins follow. `discover_boards` returns provider board evidence and its own scoped continuation; it never creates canonical items or subscriptions. The host allocates source references when the user follows a discovered board.

Inject `PublicFetchPort` with actual source authorization, public browser/network policy, deadlines and byte bounds. Anonymous anti-CSRF/request context belongs to the host and must not borrow connected-user credentials. Retain exact raw responses per operation before preparation. Expected digests select retained snapshots; missing or changed snapshots fail. HTTP 304 needs exact authorized cached bytes. The host must keep canonical continuations opaque and reauthorize account/profile, source, executor, generation and operation attempts before network and owner effects.

`CanonicalEntryPort` resolves the global pin identity, prepares through `rss-acquisition::prepare_entry` and allocates canonical item, observation and ordered media IDs. Media provider keys are optional evidence; positions never become invented stable IDs. Pin links stay Pinterest pin URLs; an outbound article link does not replace canonical pin identity. Repins with distinct provider IDs remain distinct even when they share an image. Preserve Partial gallery members not mentioned by a later response. Story text/sticker blocks are not fabricated media files; unsupported blocks fail visibly rather than erase the gallery.

After coordinated registration, run `cargo test --locked --manifest-path rss/Cargo.toml -p rss-provider-pinterest --test public` under the active preparation gate. The existing public target includes the connected contract tests. Disposable callbacks and synthetic raw responses need no network or credentials. They do not prove public availability, full immutable history, database commits or host adoption. On challenge, denial, expiry, rate limiting, missing bookmarks or a repeated cursor, retain the previous canonical checkpoint and report the typed failure.

</topic>

<topic id="connected-board">

V5 video durations are milliseconds. Exact unsigned integers and representable nonnegative integral floating-point values retain that duration; null or absent values remain unknown. Positive fractional milliseconds remain unknown (`None`) because sub-millisecond precision is unsupported; they are never rounded. Negative, malformed, nonfinite or out-of-u64-range values fail admission.

`connected::AuthorizedPinterestProvider<F,C>` acquires pins from one OAuth-authorized board through v5. Its `AuthorizedContext` contains the numeric external account, `BoardBinding` numeric board ID and canonical source URL, connection/account scope, exact FollowSource capture intent, current granted scopes and lease generation. The host issues this binding after actually resolving the selected URL and must attest it through `AuthorizedFetchPort::current`; a caller's URL or numeric ID alone is not authority. Keep credentials and OAuth refresh outside this crate. The adapter requests the actual token account, the exact board and its pins without an ads-account override. Successful board permission and matching ID/owner/privacy are required before pin preparation. A collaborative board owner may differ from the connected account username. Every returned pin must belong to the selected board. Board membership does not imply authorship or new destination grants.

Use `PublicBoard` only for actual PUBLIC boards, with the connection reference retained. Use `PrivateSource` only for SECRET or PROTECTED boards. Require user_accounts:read, boards:read and pins:read; SECRET additionally requires boards:read_secret and pins:read_secret. Current host checks enforce the same OAuth principal, lease, scopes, board permission and intent around asynchronous fetch/preparation and before return. The host must hold its lease and atomically recheck authorization during canonical/checkpoint settlement. Metadata never grants broader visibility. Home, Following, own uploads, profile discovery and subscription import remain unsupported by this adapter; saved board pins never substitute for those modes.

Raw v5 responses pass bounded duplicate-key/depth admission. Explicit image/video URLs and ordered declared multi-media entries become Partial evidence; unsupported or missing media fails, and no original URL or full gallery is fabricated. Mutable traversal remains Partial. VerifiedEmpty requires an actual positive board read with zero pin count and an empty terminal selected-board document. Failure, unknown count and malformed responses never become empty success. Continuations bind source revision, exact numeric account/board/source URL/mode/connection and the existing subscription/executor epoch; offsets require exact retained response digests. A renewed credential lease may replay original evidence but cannot change its retained bytes. Secret values and renewable generation are not copied into the durable cursor. Owning synthetic cases do not establish live customer access, ordinary authorization UX or host persistence.

</topic>

<topic id="browser-home">

`connected::home::BrowserHomeProvider<F,C>` implements only HomeForYou, separately from the OAuth-board adapter. Its `BrowserHomeContext` has its own connection, numeric external account, owner scope, exact FollowSource intent and current browser lease generation. The source is the Pinterest root URL. `BrowserHomeFetchPort::current` must attest that the actual authenticated browser session belongs to that exact account/connection and admitted intent; reject anonymous fallback, expired/superseded attempts and unrelated OAuth credentials. There is no invented response identity field. The host owns credentials, CSRF headers, session refresh, raw retained responses and atomic owner/checkpoint admission; no automatic login or session extraction is provided.

The fixed UserHomefeedResource/get request uses GET initially and POST with a form body for provider bookmark pages. Options use hf_grid and false in_nux/in_news_hub/static_feed flags. The parser admits only successful code-zero v3_home_feed envelopes, bounded raw pin arrays and the singular resource_response.bookmark. It reuses the existing pin/media parser and its visibility checks. Existing public-resource terminal bookmark handling applies; new sentinels are not inferred. Unknown or missing media fails. Nonempty terminal results remain Partial, and fresh empty results fail as unverified even if a bookmark is present. A terminal empty continuation may settle only its existing Partial checkpoint; it is never verified empty Home.

Cursors bind the browser principal, connection, owner, source URL/revision and standard subscription/executor epoch. Same-document offsets require original retained bytes, renewed leases reauthorize that original evidence, and changed identities/digests or bookmark loops fail. No OAuth board binding or dummy board is involved. The source study includes a captured request and authored transport fixtures, not a captured nonempty Home response or live authenticated identity proof. The owning tests are synthetic adapter checks; host browser transport and actual Home acquisition remain unproven. Following remains unsupported.
