<topic id="contracts">

# RSS

Rust source and acquisition contracts for independently hosted RSS. hsscrap owns item identity, capture and immutable observations. RSS owns subscriptions, access partitions, source appearances and independent read/bookmark state. Host adapters authorize operations and supply network, credentials, storage and durable checkpoint commits.

The current foundation is `rss-contracts`. From repository root, build with `cargo build --manifest-path rss/Cargo.toml`. Focused contract proof uses `cargo test --manifest-path rss/Cargo.toml -p rss-contracts --test contracts`. Follow preparation and coordinated build rules first. No service or credentials are needed for these checks. Provider acquisition, GUI, persistence and host adoption are incomplete.

AccessPartition validates public versus connected mode. Public profile, Reels, board and channel modes remain distinct. Connected Following, actual Home/For You, private sources, own uploads and subscription import cannot substitute for one another. Capability availability is an adapter declaration, not proof of source access. VerifiedEmpty requires explicit selected-source evidence; failures, expiry and partial acquisition retain separate states.

An account-owned source may feed a distinct authorized profile partition. Providers validate a nonempty bounded source owner and exact selected source reference; they do not equate catalogue ownership with capture access. Construct each provider from the canonical selected source record. The host AuthorityPort, AcquisitionOwner and transport/canonical-preparation ports must freshly verify account ownership, profile selection, source configuration, executor and generation before network or owner effects, including redirects and replay. Source and partition IDs are never grants.

Continuation binds subscription, source, access partition, executor and generation. It cannot be used as a WallCursor. CheckpointOwner records accepted item-owner outcomes and source appearances before acknowledging the continuation. A lost response requires scoped operation lookup; pending or unknown outcomes do not authorize advancing a checkpoint. No credential bytes or database/HTTP-framework types appear in these contracts. Optional hsscrap extensions and nullable legacy history remain intact.

<topic id="source-library">

`rss-core` provides pure reducers for account-owned sources, many-to-many groups, source display-name editing, pause/resume, group-specific keyword and priority rules, profile selection and independent appearance state. Run its focused cases with `cargo test --manifest-path rss/Cargo.toml -p rss-core --test catalogue` after the coordinated preparation gate.

Pass an authorized owner scope and expected library revision to each mutation. The returned snapshot is a proposed next state. A host must persist it with an atomic compare-and-swap, reject stale commits and authorize the selected profile. Pure reducer tests do not prove that persistence boundary. Display-name editing preserves provider/source URL identity; changing the followed target uses a new follow intent.

One source selected through several groups schedules once. Removing a group or membership preserves the source and all separately owned captures, item tags and project placements. Per-member rules keep each group's keywords and priority separate; the host supplies finite rule limits and account keyword budget. Existing Portal collection rules supplied the trim, printable-text and case-insensitive uniqueness behavior. Detach removes only that membership's rule. Source and group removal clean their own rules.

Profile selection intersects host-authorized sources before counts or acquisition. Item grouping preserves each appearance-state ID and its exact read/bookmark booleans, including contradictory historical rows. It never aggregates them with OR/AND. Host authorization must also filter access partitions; matching IDs carry no grants.

<topic id="acquisition">

`rss-acquisition` supplies serializable per-subscription job transitions and the Save URL capture bridge. The host persists each transition with its own atomic revision guard, authorizes the selected account/source, supplies monotonic ticks and enforces the returned deadline. It must persist `begin_commit` before item-owner effects. Running and uncertain jobs both reserve concurrency until canonical reconciliation; cancellation requests do not prove termination. Queue capacity, attempt count, timeout and exponential backoff are finite host inputs. One subscription can have one outstanding page operation across its profile views. Terminal removal does not change the canonical source checkpoint.

`JobQueue::settle_cancelled(&SourceRequest, &HostRef)` releases a cancelled Running or AwaitingRecovery reservation only through an explicit host call with the complete unchanged request and configured executor. An exact Cancelled replay is idempotent; rejected transitions leave the queue unchanged. Before calling, the host must prove genuine worker termination and canonically reconcile every persisted child intent as committed, rejected or never started. Atomically persist the proposed queue with attempt retirement and its full source/journal fences. Preserve partial captures and earlier source state. This pure transition certifies no external termination, creates no `AcknowledgedPage` and never advances the source checkpoint. Validate its public API with `cargo test --locked --manifest-path rss/Cargo.toml -p rss-acquisition --test jobs` under the coordinated build owner; native fixtures do not replace actual host cancellation and recovery proof.

`save_url` accepts the existing `CaptureIntent::SaveUrl` and hsscrap `URLCapture`. It checks exact URL intent, actor, scope and command bounds. It reconciles operation identity through `ItemOwner`, drives existing Pending operations through `MutationCoordinator::recover`, and rereads the exact stored capture before returning its committed receipt. Enrichment and following a source are separate operations. Owner ports must enforce idempotency and intent reuse atomically. Pending, lost and unknown outcomes never authorize a new logical operation or source continuation.

`ItemOwner::inspect` freshly authorizes the actor's account/profile view. An account-owned item's owner scope can differ from its authorized capture/observation partition. Readback validates the native item and nonempty owner scope, exact item/capture/observation identity and stream access partition, source and sequence; it does not equate item ownership with the profile view. Invalid capture readback after owner effects remains an unknown outcome and requires reconciliation.

The identity-aware ingestion source candidate consumes hsscrap's published URL/provider identity ports. Resolve URL and optional reliable provider identity before the host allocates a canonical item. Conflicting canonical matches fail. `prepare_entry` injects `EntryAllocator` to allocate capture records, then commits and rereads the capture before reserving the observation stream/sequence. A provider fills metadata on that reservation; changing reserved IDs, sequence or provenance rejects. A reliable nonempty provider identity is asserted only when no current canonical assertion exists, after observation commitment and canonical readback using a freshly resolved owner revision guard. URL-only sources need no invented provider ID. Existing appearance history, including unknown first-seen dates, is preserved.

`EntryAllocator::inspect_identity(request, execution_ref, &IdentityQuery)` is a mandatory canonical owner tuple read with current attempt, account/profile and source authorization; an allocation cache is not that proof. This new required trait method breaks source compatibility for existing `EntryAllocator` implementations; migrate each implementation when adopting this pinned revision. Identity reuse preserves the immutable identity mutation rules. Repeated reliable-ID refreshes preserve the original `SourceIdentity`, including its ID and verifying observation. Preparation and checkpointing reread that exact assertion, its active mapping, and the original Available verifying observation with its matching scoped stream namespace. A newer page contributes only its actual capture and observation outcomes. If the assertion verifies this same page's durable reserved observation, replay the original full identity allocation and require its exact canonical operation outcome, preserving the third receipt and byte-identical batch intent after a lost reply. Never invent an old operation context, duplicate an assertion or relabel a new observation as its original verification. Missing, retired, changed, conflicting or denied identity evidence prevents checkpoint progress while preserving committed captures. The fixture owner rejects duplicate active tuples and identity-ID reuse; focused ingestion cases cover refresh, same-page checkpoint replay and fresh identity-proof failures. These component fixtures do not establish host owner admission or disk atomicity.

Initial metadata selection is an explicit native owner intent. `prepare_entry` proposes it only after a create-only capture and an actual pristine postcapture owner snapshot pass `hsscrap::metadata::initial_observation`. `reserve_observation` takes that optional proposal after its identity argument and returns the original winning `ObservationAllocation.initial`. Save the choice before reserving a stream or executing observation effects. Existing stream/stage records without a guard keep ordinary acceptance; never upgrade a legacy allocation. Exact retries return the retained guard even when the current snapshot is no longer pristine. Never replace it with a refreshed preimage or discard it after an unknown result. Contradictory retained intent rejects.

The explicit owner command atomically accepts and initially selects one observation with one item revision and one actual owner outcome. It requires the original revision-one item, exact sole SourceIngest first capture, no prior metadata/gallery/overrides and the exact fresh stream. User Clear or manual/other-stream changes invalidate that original guard; ordinary acceptance remains unchanged. A later user selection change does not invalidate the immutable committed observation or authorize reselecting it during replay. The fresh reliable-ID path still contributes three canonical outcomes, so an85-entry host page fits255 outcome references. Hosts adopt the explicit command through their real owner transaction, not wall metadata fallbacks.

`AcquisitionOwner::admit` checks the current canonical subscription and opaque host-issued attempt before provider work and owner mutations. It must reject expired, cancelled or superseded attempts and changed executor/generation. Existing `AuthorityPort` checks account/source authority. Hosts bind allocated child operations to that admitted attempt and repeat authorization and epoch checks atomically inside each owner mutation; a caller's request equality is only a stale-result fence. Host credentials, worker lifecycle and scheduling remain outside the portable crate.

`EntryAllocator` resolves actual operation-journal references and rereads their exact canonical outcomes. These remain distinct from per-owner step receipts. `commit_page` rereads captures, accepted observations, source identities and operation references before submitting the existing full `BatchCommit`. The checkpoint owner atomically compares the complete immutable batch on every call, verifies all referenced operations and current authority, then commits appearances and continuation together. Only an exact-batch Committed result followed by a matching scoped lookup produces `AcknowledgedPage`. A lost reply or Pending cannot be acknowledged from lookup alone; retry the identical full batch. The accepted generation is the subscription/executor fence and stays constant across pages; host storage revisions are separate.

`JobQueue::advance` consumes the valid acknowledgement and a host-issued next operation identity, validates the complete next request, then replaces the prior reservation with its acknowledged continuation in one transition. Rejection leaves the old queue unchanged. The host atomically persists old-or-new queue state and retires the previous attempt; do not remove a page job and enqueue its continuation in separate durable writes. Persist immutable page/batch intent before owner effects so a restart can retry the same full commit from the retained old job. The checkpoint remains canonical. A final page uses `JobQueue::acknowledge` to complete its reservation. A verified empty terminal document reached through an existing source continuation uses the reserved `TERMINAL_SOURCE_DOCUMENT` Partial reason with zero entries, Partial coverage and no outgoing cursor. Its exact checkpoint can settle the job without asserting an empty/complete source or clearing earlier appearances. Fresh requests and ordinary empty Partial/error pages cannot use this settlement. Provider continuation remains separate from `WallCursor`; provider failure preserves canonical captures and cannot advance a checkpoint. No network client, credential store, database, scheduler service or GUI is included. Source changes require focused proof with `cargo test --locked --manifest-path rss/Cargo.toml -p rss-acquisition --tests` from repository root under the coordinated build owner and preparation gate. Fourteen native ingestion cases pass against local owner contracts, including immutable identity reuse, exact same-page checkpoint replay and terminal empty archive settlement. The existing five capture cases retain their earlier proof; the terminal-document extension does not change capture inputs. These fixtures do not prove host disk atomicity, persistence or real provider access.

Current primary-source inspection on 2026-10-23 confirmed that [Karakeep's feed worker](https://github.com/karakeep-app/karakeep/blob/main/apps/workers/workers/feedWorker.ts) uses per-feed idempotency, user grouping and bounded worker concurrency/timeouts. Reuse the existing RSS contracts and hsscrap owner recovery rather than introduce a second queue authority or metadata schema. Keep network scheduling in the host and return deterministic transitions. The main risks are duplicate profile scheduling, expired worker effects and lost owner replies. Subscription uniqueness, executor/deadline checks, retained uncertain reservations and canonical owner rereads address those risks. Queue/recovery tests cover these decisions; durable host and source acquisition proof remains separate.

<topic id="independent-consumer">

MT-016 research inspected on 2026-10-23: the current Cargo Book on [Git dependencies](https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html), [packaging](https://doc.rust-lang.org/cargo/commands/cargo-package.html) and [overrides](https://doc.rust-lang.org/cargo/reference/overriding-dependencies.html), plus the existing hsscrap independent consumer driver and actual RSS public APIs. Cargo selects all Git subcrates from the requested revision, while packaged manifests replace path dependencies with registry locations. Existing packages are private and their version labels do not prove registry availability. Reuse exact Git consumption and a canonical source archive; reject a fabricated crates.io release or assuming VCS metadata proves file contents.

The consumer driver builds outside both host workspaces with no shared database, network source or provider credentials. Select headless native, native GUI/public-provider and actual WebAssembly outputs separately. Every Git RSS/hsscrap/canonical-JSON dependency must resolve to one exact requested commit. Metadata records actual features and target, rejects host/DB/local-path dependencies and checks the core closure has no concrete provider or GUI. Native workflows use public source/group/profile reducers, query state, serialized job recovery, RSS/scientific parsing and optional actual GUI/public-provider entry points. Their synthetic data does not prove canonical persistence or provider availability.

The browser consumer compiles an external cdylib that calls the published Rust `RssBridge`, generates exact wasm-bindgen web bindings and instantiates those actual bytes in Node. That artifact is distinct from either native binary and from real browser/Portal adoption. The driver records hashes of actual manifests, locks, example inputs, copied binaries, WASM, bindings and canonical source archive, with exact source/target/features. Copy native binaries before another feature build can overwrite their Cargo output path. Generated artifacts stay in a configurable ignored output root. Existing source files and independent verifier reads determine provenance; a self-authored result alone does not establish canonical publication.

Source selection discovers the actual Git root and checks all three selected manifests before any build. It supports current root folders and historical `assets/` revisions. For a source-layout-only check, run `python rss/tests/consumer/prove.py --revision <exact-commit> --source-only` with the existing absolute `CARGO_TARGET_DIR`. This archives the exact source closure and reports `source-pass` with runtime `not-run`; it proves no compiled output or runtime behavior.

Run only after independent publication/adoption and coordinated preparation/native-slot clearance. Supply an exact immutable revision and configured existing Cargo/Rust/Git/wasm-bindgen/Node tools and shared target. Missing tools, wrong pins, changed archive selection or failed runtime calls stop with retained logs. Keep previous output directories for recovery; never reinterpret an uncertain run as a release. The first actual run at `6311655576f52fd615f5804c55466e7643de000d` passed four headless workflows, seven GUI/public-provider workflows and eight directly instantiated WASM checks. The generated module exports the actual `RssBridge`, including query composition and details-boundary methods. Its details checks cover rejected missing tickets, not successful panel rendering. Metadata selected six, fourteen and seven exact-pin Git packages respectively; all active graphs were acyclic, with the headless/core dependency boundaries preserved. Canonical WP state records artifact identities and independent verification. Generated native binaries, bindings and the 140-file canonical source archive are local outputs, not uploaded prebuilt releases. Full host, live-provider and connected-mode gates remain outstanding.
